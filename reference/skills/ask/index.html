    /dp-skills:ask¶

    사용자가 구현된 기능의 동작·위치를 물을 때 사용한다 — 팀 컨텍스트 → 소스 순 탐색으로 답하는 읽기 전용 질의. 활성 작업과 무관한 질문도 대상. 코드 수정·구현 요청에는 발동하지 않고, 같은 세션의 후속 질문에도 재발동하지 않는다. 기획서 검색은 /dp-skills:confl, 컨텍스트 누적은 /dp-skills:discover. 탐색 순서·개선 모드는 본문.

    구현된 기능에 대한 질의에 팀 컨텍스트 → 소스 순의 고정된 탐색 경로로 답한다.

    질문: $ARGUMENTS — 구현된 기능에 대한 질의 (필수)

    읽기 전용 계약 — 본 스킬은 STATE.md·.agent-state.yml·팀 컨텍스트·소비 레포 소스 어느 것도 Write/Edit 하지 않는다. 질의가 활성 작업을 전환·오염시키지 않으며 (stateless — switch 와 동형), 답변을 어떤 파일에도 캐시하지 않는다. 팀 컨텍스트의 생산자는 /dp-skills:discover 단독이다 — 탐색 중 발견한 지식 갭·drift 는 discover 실행 제안으로만 환류한다.

    사전 확인¶

    preamble.md 의 P1 수행.

    P-1·P2~P4 비적용 사유는 preamble § 스킬별 P 절차 적용표의 ask 각주 참조.

    • $ARGUMENTS (질문) 누락 시 아래 안내 후 종료:
    사용법: /dp-skills:ask {질문}
예시:   /dp-skills:ask 주문 취소 시 재고 복원은 어디서 처리돼?
    • workspace/{TEAM}/STATE.md 를 soft-read 한다: 활성 행이 있으면 mode·이름을 기억해 둔다 (절차 1 의 입력). 활성 행 부재·issue 모드·corrupt 어느 것도 종료 사유가 아니다 — corrupt 는 WARN 1줄 표기 후 계속한다 (switch 선례. 질의는 활성 작업과 독립이 주 사용처).

    수행 절차¶

    1. 스코프 판정 — 활성 작업 관련성¶

    활성 작업이 있으면 그 폴더의 식별 표면만 질문과 대조한다:

    • project: project.md 의 목표 절 + features/ 파일명 (NN-{slug}.md — 본문 Read 없음, 대조 비용 상한)
    • issue: issue.md 의 H1

    관련이 분명하면 해당 문서 (project.md·해당 feature 파일·issue.md) 를 1차 컨텍스트로 Read 한다. 무관하거나 판단이 불확실하면 로드 없이 2단계로 — 불확실을 관련으로 기울이지 않는다 (활성 폴더 로드는 가속이지 정답의 전제가 아니다). 활성 작업이 없으면 이 단계를 건너뛴다.

    2. 팀 컨텍스트 탐색 (best-effort)¶

    1. workspace/{TEAM}/context/MANIFEST.md Read — 질문이 속한 도메인 판정.
    2. 판정된 도메인의 컨트랙트 경로를 Read (존재하는 것만): scope/{domain}.md · rules/{domain}.md · 질문이 도메인 경계를 걸치면 boundaries/{A}--{B}.md.
    3. MANIFEST 부재 시 종료하지 않는다 — 답변 앞에 아래 1줄을 고지하고 3단계로 직행한다 (조용한 degrade 금지 — 사용자가 컨텍스트 부재를 인지해야 한다):

    팀 컨텍스트 없음 — 소스만으로 답합니다. 도메인 지식 누적은 /dp-skills:discover.

    3. 소스 확증¶

    scope 문서가 가리키는 진입점에서 Read/Grep 으로 추적한다. 범위가 넓으면 Explore 서브에이전트에 위임한다 (읽기 전용 탐색).

    세부 (계산식·분기·조건·필드 의미) 는 반드시 소스에서 확인하고 file:line 으로 인용한다 — scope 문서는 소스로 가는 지도이지 답의 근거가 아니다 (discover 기재 층위와 대칭: 컨텍스트에는 구현이 기재되지 않으므로, 지도가 가리키는 소스가 유일한 근거다).

    4. 답변¶

    • 결론 먼저 — 질문에 대한 직접 답 1~3문장.
    • 동작 설명 — 소스 file:line 인용 기반.
    • 근거 출처 표기 — 컨텍스트 문서에서 얻은 위치 / 소스에서 직접 확인한 사실을 구분해 한 줄로.
    • (조건부) drift 절 — 탐색 중 팀 컨텍스트 기재와 소스가 불일치하면 보고하고 /dp-skills:discover {entry} {domain} 갱신을 제안한다. 직접 수정하지 않는다 (읽기 전용 계약).
    • (조건부) 개선안 절 — 절차 5 발동 시만.

    같은 세션의 후속 질문은 본 스킬을 재호출하지 않고 이미 로드된 컨텍스트 위에서 직접 답한다 — 소스 file:line 인용 규율은 후속 답변에도 유지한다.

    5. 개선 모드 (조건부)¶

    질문에 개선 의도의 가정형 표현 (개선·리팩터·최적화·"더 낫게"·"바꾸면 어때" 류) 이 있을 때만 답변 말미에 개선안 절을 추가한다:

    • 개선안 요지 — 현재 구조의 제약 → 제안 방향.
    • 실행 라우팅: 단발 수정 → /dp-skills:issue {이슈명} / 기능 단위 → /dp-skills:create-feature. 자동 실행 없음 — 실행은 사용자 명시 호출.

    명령형 ("바꿔줘"·"고쳐줘") 은 개선 질의가 아니라 수정 요청 — 본 스킬의 발동 대상이 아니다 (frontmatter anti-trigger 와 일관). 판단이 애매하면 절 생략이 기본 (질의응답이 본분).

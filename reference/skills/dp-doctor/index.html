    /dp-skills:dp-doctor¶

    dp-skills 워크스페이스·팀·프로젝트의 정합성을 검사한다. 상태 이상·드리프트·부분 설정이 의심될 때, 또는 정기 점검·진단을 원할 때 사용한다. 구조 파일 존재·state 스키마·플래그 실상 일치를 검사해 STATE corrupt 같은 조용한 문제를 조기 감지한다.

    프로젝트·팀·workspace 정합성을 검사한다.

    대상: $ARGUMENTS (생략 시 STATE.md 의 진행중 프로젝트)

    동작¶

    아래 Bash 명령을 실행해 결과를 사용자에게 그대로 출력한다:

    python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace

    인자로 프로젝트명이 전달되면 --project 플래그로 전달:

    python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace --project {PROJECT}

    스크립트가 정합성을 검사하고 ANSI 컬러 포함 결과를 stdout 으로 출력한다. exit code:

    • 0 — ERROR 없음 (PASS / WARN 만)
    • 1 — ERROR 1 건 이상

    출력 형식·문구의 SSOT 는 doctor.py stdout 이다 — 본 문서에 출력 예시를 두지 않는다 (버전·심각도 드리프트 방지).

    검사 범위¶

    workspace · 팀 · 프로젝트 세 계층의 구조 파일 존재 · state 스키마 · 플래그와 실상의 일치 · 공유 context 위생을 검사한다.

    개별 검사 목록은 여기에 두지 않는다 — 무엇을 검사하는지의 SSOT 는 doctor.py 실행 결과다 (:37 의 출력 SSOT 조항과 같은 이유). 검사는 릴리즈마다 늘어나므로 문서에 목록을 두면 그 목록이 곧 드리프트한다. 지금 무엇을 검사하는지 알고 싶으면 실행해 보는 것이 정확하다 — 각 항목은 심각도 라벨·근거·처방을 함께 출력한다.

    state 필드의 의미·허용값: state-schema.md

    언제 실행하나¶

    • 프로젝트 활성화 직후 상태 확인 (/dp-skills:project {이름} 후)
    • analyze · tdd 실행 직후 state 갱신 확인
    • drift 의심 시 수동 점검
    • 신규 팀 합류 시 workspace 구조 검증

    향후 hook 연동 (post-project / post-analyze / post-tdd) 으로 자동 실행 예정.

    실패 진단 모드 (--diagnose)¶

    기존 정합성 검사와 독립. 런타임 실패 패턴을 4-phase (capture → diagnose → reduce → report) 로 진단한다.

    python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace --diagnose
python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace --diagnose --project MyProject

    검출 패턴:

    패턴 의미 판정 근거
    loop 에이전트 루프 의심 .plan.md 에 동일 설명 3회+ 반복
    red-miss TDD Red 증거 누락 tdd: true 인데 스텝 대비 [Red] 마크 부족
    repeat-not-ready 동일 feature 2회+ 반려 .plan.md / project.md 에 NOT_READY · 반려 누적
    scope-violation .focus.md scope 외 편집 git diff 파일과 scope 불일치
    none 정상 감지된 패턴 없음

    출력:

    ## DIAGNOSIS
- project: MyProject
- pattern: red-miss | repeat-not-ready | loop | scope-violation | none
- evidence: {근거 요약}
- recommended_action: {권장 액션}
- confidence: high | medium

    exit code: 항상 0 (진단이 정상 수행된 경우) — --diagnose 는 정보성 리포트로, 패턴 감지 여부는 exit code 가 아니라 DIAGNOSIS 블록 텍스트로 전달한다 (--schema/기본 모드의 ERROR=1 계약과의 충돌 방지 — diagnose.py 주석 참조). 복수 패턴 동시 감지 시 우선순위는 red-miss > repeat-not-ready > scope-violation > loop 이며 이 때 confidence: medium.

    언제 호출:

    • evaluator 가 같은 feature 에 status: NOT_READY 를 2회 출력했을 때
    • 에이전트가 동일 도구·명령을 반복하는 것으로 의심될 때
    • 체크리스트·REPORT 기록이 비어있는데 완료 선언된 경우 (Red 증거 누락 의심)

    스키마 검사 모드 (--schema)¶

    플러그인 구조 전용 검사. workspace 와 무관.

    python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py --schema

    검사 범위: .claude-plugin/PLUGIN_SCHEMA_NOTES.md 기준.

    • plugin.json 필수·금지 키
    • hooks/hooks.json matcher 허용값
    • skills/*/SKILL.md · agents/*.md frontmatter
    • version ↔ git tag 일치 (불일치는 WARN)

    CI 에서 자동 실행 — .github/workflows/validate.yml.

    측정 모드 (--oq-stats)¶

    Open Questions 통계를 JSON 으로 출력한다 — planner 의 OQ 가드가 실제로 작동하는지 측정하는 용도라 일상 진단 경로는 아니다.

    python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace --oq-stats
python3 ${CLAUDE_PLUGIN_ROOT}/tools/doctor.py workspace --oq-stats --stale-days 14

    --stale-days 는 stale 판정 임계값 (기본 7일, feature 파일 mtime 기준).

    제약¶

    • 스크립트는 순수 파이썬 stdlib 만 사용 (외부 의존 없음)
    • 기본 실행 검사는 비파괴 — 읽기만 함, 파일 수정 안 함 (0.23.2 부터 .gitignore secret 패턴 주입도 기본 실행에서는 WARN 만 — 종전엔 자동 append 로 이 계약을 위반했다)
    • 실패 시 fix 제안은 출력하되 자동 적용 안 함. auto-fixable 표시가 붙은 항목만 사용자가 doctor --fix 를 명시 실행했을 때 수정된다.

    context-load-audit.py¶

    dp-skills context-load-audit — 사이클 서브에이전트의 컨텍스트 로드량과 늦은 단계 준수율 측정.

    컨텍스트 다이어트 (PLAN-ai-reader-diet Phase B) 의 효과 판정 도구. Claude Code 세션 트랜스크립트에서 dp-skills:ag-* 서브에이전트 호출마다 ① 무엇을 얼마나 읽었는지 ② files_to_read 를 실제로 로드했는지 ③ 절차 후반 단계를 수행했는지를 집계한다. 읽기 전용이며 표준 라이브러리만 쓴다.

    출력 계약: 숫자와 분류 라벨 (agentType·파일 클래스·로드 방식) 만 낸다. 트랜스크립트 원문 (명령·프롬프트·도구 결과) 은 어떤 모드에서도 출력하지 않는다. 파일 클래스는 경로를 정규화한 라벨이다 (ws:projects/*/project.md, plugin:skills/context/shared/coding.md).

    Usage: python3 context-load-audit.py # 로드량 + files_to_read + 늦은 단계 준수율 python3 context-load-audit.py --json # 같은 집계를 JSON 으로 python3 context-load-audit.py --since 2026-10-01 # 기간 한정 (적용 전후 비교용; --until 도 있음) --projects-dir PATH # 트랜스크립트 루트 (기본 ~/.claude/projects) --bench-pattern REGEX # 벤치 실행 slug (기본 -eval-runs-) — 실사용과 분리 집계

    측정 규약 (PLAN-ai-reader-diet § 4 B-2): - 로드량 = tool_result 본문 길이 (실제로 컨텍스트에 들어간 chars). Read 와 Bash (cat·sed -n·head·tail·nl·awk) 를 함께 센다. - 로드 방식 4갈래: full (전문) / partial (sed -n·head·tail·Read offset·limit) / preview (30KB 초과로 <persisted-output> 미리보기만 남고 저장 파일을 다시 읽지 않음) / none (files_to_read 에 있었는데 로드하지 않음). 한 파일을 여러 번 읽으면 가장 강한 방식. - 쓰기는 도구가 아니라 대상 파일로 센다 — Edit·Write·MultiEdit 와 Bash (sed -i·perl -i·리다이렉트·tee·write_text·open(…,'w')·cp/mv). - 호출 프롬프트가 해당 단계를 금지한 호출 (예: "project.md 편집 금지") 은 분모에서 빼고 excluded_by_prompt 로 따로 센다. - 슬라이스 (orchestrate-load read_ranges): 호출 안에서 읽은 줄 집합을 누적해 판정한다 (Read offset·limit, sed -n 'a,bp', head -n N, 전문 Read·cat = 전체). followed = 지정 범위 전부를 덮음, escaped = 전문, partial = 일부만, none. 결손 (planner 한정) = 대상 plan 이 인용한 feature 중 슬라이스에서 빠진 소절 (slices.dropped_ranges) 을 끝내 읽지 않은 것. critic 은 plan 참조가 이미 R 에 들어가 구조적으로 0 이라 세지 않는다. 판정 정규식은 orchestrate-load feature_refs 재사용. - critic 이력 누적은 재호출 (같은 critic 파일에 앞선 쓰기가 있는 호출) 만 분모로 삼고, 판정은 critic-lint lint_history (헤딩 기준) 로 한다. 본문을 복원할 수 없는 Bash 쓰기는 undecidable.

    판정 근거와 한계: - 순회: <slug>/<session>/subagents/agent-*.jsonl + agent-*.meta.json 의 agentType. - Bash 대상 파일은 명령 안의 경로 토큰 (.md·.yml·.yaml·.json) 으로 추정한다. 글롭·변수 경로는 클래스 라벨로만 남는다. 묶음 읽기의 chars 는 대상 수로 균등 배분. - status 는 마지막 assistant 텍스트의 VERIFICATION REPORT status: 값이다. - Slack 은 slack-notify.py … --event complete Bash 호출 여부만 본다 (no-op 여부 무관). - wrapper 시스템 프롬프트 (agents/ag-*.md) 는 트랜스크립트에 남지 않아 로드량에 없다 — 호출마다 파일 크기만큼 더해진다고 보면 된다.

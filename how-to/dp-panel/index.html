    작업 패널 (dp-panel)¶

    한 줄 요약

    /dp-panel 로 켜는 버튼 패널입니다. 커밋·PR·셀프 리뷰, 다음에 부를 에이전트, 응답의 a)/b)/c) 선택지를 프롬프트 입력 없이 버튼으로 진행하고, 지금 모드·focus·실행 중인 서브에이전트·백그라운드 셸 출력·내 열린 PR 을 한 화면에서 봅니다.

    언제 쓰나¶

    • /dp-skills:commit → /dp-skills:pr 같은 정해진 다음 단계를 매번 타이핑하기 번거로울 때
    • run-cycle 정지 보고처럼 응답이 a) b) c) 선택지로 끝나서 답을 고르기만 하면 될 때
    • characterize (소스 잠금)·TDD·QA 중 지금 어떤 모드인지, 남아 있는 focus 가 있는지 확인하고 싶을 때
    • 서브에이전트 (@ag-generator 등) 가 지금 무엇을 하는 중인지, 백그라운드로 띄운 dev 서버·테스트가 어떻게 돌고 있는지 보고 싶을 때
    • 내가 연 PR 중 아직 머지되지 않은 것을 모아 보고 싶을 때

    버튼은 스킬·에이전트를 시작만 합니다. /dp-skills:pr 의 사용자 확인 같은 게이트는 그대로 거칩니다.

    전제¶

    • dp-skills 와 dp-panel 둘 다 설치 (/plugin install dp-panel@deali-skills) — 활성 작업은 설치된 dp-skills 의 tools/switch-scan.py 로 읽습니다
    • Claude Code 2.1.288 이상 — 패널은 함수 훅 API (early access) 로 그려서, 그보다 낮은 버전에서는 /dp-panel 이 나타나지 않습니다
    • 커밋·PR 영역은 git 저장소, 내 PR 목록은 gh 인증 (gh auth status) 이 필요합니다
    • 다음 진행·모드·focus 영역은 세션 폴더에 workspace/TEAM.md 가 있을 때만 채워집니다

    절차¶

    /dp-panel      # 켜기 — 다시 입력하면 끄기. 켜고 끈 상태는 다음 세션에도 유지

    패널은 구역마다 둥근 테두리 카드로 나뉩니다. 카드 제목 줄 오른쪽에 요약 (브랜치·작업명·개수) 이 붙어 카드만 훑어도 핵심이 보입니다. 위에서 아래로 "지금 → 다음 → 돌고 있는 것 → 밖에 나가 있는 것" 순서입니다.

    ╭ 작업 ─────────────────────────────── feature/order-refund ╮

    버튼 옆 글자는 패널을 클릭하거나 포커스했을 때 쓰는 단축키입니다.

    카드 보이는 것 버튼
    작업 브랜치 · 변경·미푸시·PR 숫자 타일 (값이 있으면 굵게, 0·없음이면 흐리게) · 바뀐 파일 상위 5개와 줄 수 (+ 기본색·− 흐리게) 커밋 (c) → /dp-skills:commit · PR (p) → /dp-skills:pr · 셀프 리뷰 (v) → @ag-code-reviewer · 새로고침 (r)
    다음 진행 활성 project·issue · 모드 칩 (옅은 파랑 면, characterize 는 앰버 면) · focus · 목표 진행 막대 · 첫 미완료 feature 의 사이클 4단계 지금 단계 에이전트 실행 (1) · run-cycle (목표를 다 끝내면 숨김) · 지우기 (focus)
    실행 중 에이전트 돌고 있는 서브에이전트와 최근 완료 5개 — 이름 · feature · 소요 시간 · 도구 횟수 · 마지막 도구 —
    터미널 이 세션의 백그라운드 셸 — 선택한 탭의 최근 30줄, 모든 셸의 상태·소요 시간 목록, 실행 중이면 ○ 실행 중 N 셸 탭 · 완료 정리
    내 열린 PR 현재 레포에서 내가 연 미머지 PR — 제목 줄과 흐린 상태 줄 (리뷰 상태 · dp 표식 · 브랜치), dp-skills 라벨 먼저 제목 링크 · AI리뷰

    지금 누를 주 동작은 패널 전체에서 하나만 채운 버튼입니다 — 다음 진행 동작이 있으면 그 첫 버튼, 없으면 커밋 → PR 순입니다. 변경이 없으면 커밋 버튼이, 기본 브랜치에서는 PR 버튼이 흐리게 바뀌고, 눌러도 실행하지 않고 이유를 알려 줍니다.

    다음 진행 버튼을 누르면 그 버튼이 흐린 요청함… 으로 바뀌고, 에이전트가 뜨면 실행 중… 으로 바뀝니다 (사이클 단계의 지금 칩도 실행 중 으로). 이 동안 다시 눌러도 같은 에이전트를 또 띄우지 않고 알림만 띄우며, 1차 버튼 강조도 빠집니다. 버튼으로 시작하지 않았어도 세션이 진행 중이면 (메인 턴이 돌고 있거나 실행 중인 에이전트가 있으면) 다음 진행 버튼과 run-cycle 이 모두 흐려지고, 카드에 세션이 진행 중 — 끝나면 누를 수 있습니다 가 보입니다. 에이전트가 끝나고 응답이 돌아오면 다시 누를 수 있습니다. run-cycle 버튼도 같은 방식으로 run-cycle 실행 중… 이 됩니다. 카드 사이와 카드 안 요소 사이에 여백을 두어 테두리가 붙어 보이지 않게 합니다 (데스크톱은 카드 사이 2칸·안쪽 1칸, 터미널은 카드 사이 1칸). 패널 폭이 48칸보다 좁으면 카드 요약을 제목 아래로 내리고, 숫자 타일은 한 줄 요약으로 접고, 버튼을 세로로 쌓습니다.

    색과 기호¶

    • 주조색은 파랑 하나입니다. 카드 제목·테두리, 채운 버튼, 지금 단계, 고른 탭, 실행 중 표시만 파랑이고, 숫자·본문·파일 경로는 테마의 기본 글자색입니다.
    • 끝난 것은 초록으로 칠하지 않고 흐리게 물러납니다. 상태는 기호 (✓ 끝남 · ○ 지금 · · 남음 · ✗ 실패) 로 가르므로 색이 보이지 않아도 구분됩니다.
    • 빨강은 실패·평가 미통과·변경 요청 칩에만 씁니다. PR 목록을 못 불러왔다는 안내 같은 문구는 기본 글자색입니다.
    • 앰버는 면으로만 — focus 칩과 characterize 모드 칩. 그 위 글자는 검정입니다.
    • 바탕 밝기에 맞춰 파랑을 고릅니다. 밝은 테마는 짙은 파랑 (#0052CC)·옅은 파랑 테두리 (#CCDCF5), 어두운 테마는 같은 계열의 흐린 파랑 (#8CB1E8) 과 기본 흐린 테두리입니다 — 짙은 파랑은 어두운 바탕에서 읽히지 않습니다. /config 의 테마를 따르고, auto 면 macOS 화면 모드를 읽습니다. 칩은 바탕색을 함께 정하므로 테마와 상관없이 같은 색입니다.

    실행 중 에이전트¶

    • 실행 중 (○ 파랑) 이 위, 완료 (✓ 흐림)·실패 (✗ 와 빨간 실패 칩) 가 아래입니다. 서브에이전트가 띄운 서브에이전트는 한 단계 들여 씁니다.
    • dp-skills 에이전트는 호출 프롬프트에서 feature 번호와 slug 를 읽어 함께 보여 줍니다 (#04 partial-refund).
    • 둘째 줄은 그 에이전트가 마지막으로 쓴 도구입니다 — Edit 파일 경로, Bash 명령 설명, Grep "패턴" 처럼 한 줄로 줄입니다.
    • 에이전트 이름은 시작될 때 엔진이 알려 주는 종류로 붙입니다. 시작 신호를 놓친 에이전트는 엔진 목록에서 이름을 찾고, 거기에도 없는 것 (워크플로 내부 등) 만 이름 없는 에이전트 한 줄로 묶습니다.
    • 완료는 최근 5개까지 남고, 새 프롬프트를 보내면 1개만 남깁니다. 실행 중인 에이전트가 없고 완료 기록도 없으면 카드가 나타나지 않습니다.

    터미널¶

    • Claude 가 run_in_background 로 띄운 셸 (dev 서버·테스트·빌드 등) 마다 탭이 하나 생깁니다. 탭 이름은 명령 설명입니다. 고른 탭은 파랑 밑줄 글자, 나머지는 흐린 버튼입니다.
    • 선택한 탭의 최근 30줄이 출력 창에 보입니다. 그 아래에는 탭과 상관없이 모든 셸이 한 줄씩 ○ 실행 중 · ✓ 완료 · ✗ 실패 (N) 과 소요 시간으로 나옵니다. 기록이 사라졌는데 종료 줄이 없으면 – 중단 입니다.
    • 실행 중인 셸이 있으면 카드 제목 오른쪽에 ○ 실행 중 N 이 붙고, 모두 끝나면 모두 끝남 으로 바뀝니다.
    • 출력은 2초마다 따라옵니다. 단 패널이 열려 있고 실행 중인 것이 있을 때만 읽고, 아니면 멈춥니다.
    • 완료 정리 는 끝난 셸 탭만 지웁니다. 출력은 화면에만 그리며 대화나 모델로 보내지 않습니다.

    프롬프트 위 버튼¶

    패널을 닫아 두어도 프롬프트 바로 위에 두 종류의 버튼이 뜹니다.

    • 응답 선택지 — 마지막 응답이 a) 부터 이어지는 선택지 2개 이상으로 끝나면 버튼으로 뜹니다. 누르면 b) … 처럼 그 답이 바로 전송됩니다.
    • 후속 단계 — 셀프 리뷰 리포트 (CODE REVIEW REPORT) 가 나오면 처리 경로 추천 (fix-review) 이 뜹니다.

    무엇이든 새로 입력하면 이 버튼들은 사라집니다.

    상태줄¶

    프롬프트 아래 상태줄에 dp · {작업명} · characterize · 소스 잠금 · focus 있음 · 에이전트 1 · 셸 1 처럼 지금 작업, 기본값이 아닌 모드, 실행 중인 에이전트·셸 수가 항상 표시됩니다 (실행 중인 것이 없으면 뒤 두 항목은 빠집니다).

    다음 진행 단계를 고르는 기준¶

    첫 미완료 feature (project.md ## 목표 의 첫 [ ], 취소선 중단 항목 제외) 의 산출물 파일과 critic 합의표를 봅니다. 합의표는 run-cycle 과 같은 기준으로 읽습니다 — severity 가 blocking 이고 status 가 open·deferred 인 행이 남아 있으면 구현으로 넘어가지 않습니다.

    산출물 지금 단계 · 버튼
    .plan.md 없음 계획 · @ag-planner
    plan 있음 · .plan.critic.md 없음 계획 검토 · @ag-planner-critic
    critic 합의표에 풀리지 않은 blocking 이 있음 계획 (보완) · @ag-planner — critic 지적을 반영해 합의표를 채움
    critic 합의표를 읽을 수 없음 (표도 "결함 없음" 문구도 없음) 계획 검토 · @ag-planner-critic (다시 검토)
    합의표 통과 · .eval.md 없음 구현 · @ag-generator
    .eval.md 가 NOT_READY 구현 (재작업) · @ag-generator
    .eval.md 가 READY 없음 — 체크박스만 남은 상태, run-cycle 이 보정

    버튼은 지금 단계 하나만 나옵니다. 카드에는 사이클 4단계 (계획 → 계획 검토 → 구현 → 평가) 를 ✓ 끝남 (흐림) · ○ 지금 (파랑과 지금 칩) · · 남음 (흐림) · ✗ 미통과 (빨간 미통과 칩 — critic blocking 이 남은 계획 검토, NOT_READY 평가) 로 보여 줍니다.

    구현이 끝났는지는 파일로 알 수 없어서, 합의표를 통과했고 eval 이 없으면 구현을 지금 단계로 둡니다. 다만 돌고 있거나 끝난 에이전트로 앞으로 보정합니다. 평가 에이전트가 돌고 있으면 평가가, 구현 에이전트가 끝났으면 평가가 지금 단계가 되고 버튼도 @ag-evaluator 로 바뀝니다. 끝난 단계는 feature 별로 기록해 두므로 세션을 새로 열어도 이어집니다. 미통과 단계는 건너뛰지 않습니다 — critic 이 blocking 을 남겼으면 critic 이 끝났어도 구현으로 가지 않고 계획 보완에 머뭅니다. 버튼으로 부르지 않고 세션 창에 직접 입력했거나 run-cycle 이 부른 에이전트도 같습니다. run-cycle 은 한 턴 안에서 여러 에이전트를 돌리므로, 패널은 에이전트가 끝날 때마다 산출물을 다시 읽습니다.

    목표 진행 막대는 project.md 목표 체크박스 수 (12/17) 로 그립니다. 데스크톱에서는 막대 그림 (채움 파랑·바탕 옅은 파랑) 으로, 터미널에서는 ██████░░░░ 글자 막대로 나옵니다.

    plan 이 유효한지, 합의표가 본문 챌린지와 맞는지 (critic-lint) 는 판정하지 않습니다. 정확한 재개 지점은 run-cycle 이 기준이니 애매하면 run-cycle 버튼을 쓰세요.

    패널이 보여 주지 않는 것¶

    • 다른 세션·다른 창의 Claude — 패널은 자기 세션만 봅니다.
    • 데스크톱 앱 아래쪽 터미널 패널의 탭 — 사용자가 연 셸이라 읽을 수 없습니다. 그 패널은 자체 탭이 있습니다.
    • 셸·에이전트 중지 — 패널에는 중지 버튼이 없습니다. 멈추려면 Claude 에게 직접 요청하세요.
    • 서브에이전트의 전체 대화 — 앱이 이미 보여 줍니다. 패널은 "무엇을 하는 중인지" 한 줄만 보여 줍니다.
    • 세션을 다시 시작하기 전에 띄운 셸의 출력 — 출력 위치를 기록하지 못해 "출력 경로를 읽지 못했습니다" 로 표시됩니다.

    업그레이드¶

    새 버전이 나오면 마켓플레이스를 갱신한 뒤 플러그인을 올리고 재시작합니다.

    claude plugin marketplace update deali-skills

    claude plugin update dp-panel@deali-skills --scope user
    • 설치된 버전은 claude plugin list 로 확인합니다.
    • dp-skills 도 함께 올라왔다면 claude plugin update dp-skills@deali-skills --scope user 도 실행합니다. 레포 폴더에 dp-skills 를 project 스코프로 따로 설치했다면 그 폴더에서 --scope project 로 한 번 더 실행해야 그 레포에서도 새 버전이 돕니다.
    • 적용하려면 Claude Code 를 재시작합니다. 재시작 전 세션은 이전 버전으로 계속 돕니다.

    흔한 실수¶

    • /dp-panel 이 없다고 나온다 — Claude Code 버전이 낮거나 dp-panel 을 설치하지 않은 세션입니다. 설치 뒤에는 세션을 새로 열어야 합니다.
    • 다음 진행이 "활성 dp-skills 작업 없음" — 세션 폴더에 workspace/ 가 없거나 (플러그인 레포 등) STATE.md 에 활성 행이 없습니다. /dp-skills:switch 로 전환하세요.
    • 내 PR 에 dp-skills 표식이 안 붙는다 — 레포에 dp-skills 라벨이 없으면 /dp-skills:pr 은 표식 없이 만들고 생성 명령을 알려 줍니다. 한 번 만들어 두면 이후 PR 부터 붙습니다. 표식이 없는 PR 도 목록에는 나옵니다.
    • AI 리뷰 반영을 눌렀는데 확인 창이 뜬다 — 의도된 동작입니다. /dp-skills:ai-review 는 호출 자체가 승인이라 후속 PR 까지 바로 만들기 때문에, 버튼은 한 번 더 묻습니다.
